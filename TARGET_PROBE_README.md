# Alpha8 probe FIX1: что делать сейчас

**После уже присланной записи WR повторять не нужно.** Распакуй этот полный комплект в новую папку и запускай **`TARGET_PROBE_CK.bat`**: будут только три этапа Chaos Knight. Оставь Anti-Mage основным героем, CK — управляемым врагом, и приготовь ещё одну цель из команды Anti-Mage. От лица CK бросай Chaos Bolt в указанную цель. Самим AM Counterspell не нажимай.

В FIX1 исправлены преждевременное завершение всего сбора из-за размера, застревание выборки на первых 16 эффектах и потеря счётчиков незавершённого этапа. Новый формат сохраняет сырые байты без потерь, но не повторяет одинаковые длинные блоки. У каждого этапа собственный бюджет; короткий высокий сигнал — начало, низкий — окончание записи.

Ниже описана и полная последовательность WR+CK для отдельного `TARGET_PROBE.bat`; **сейчас тебе нужен только CK-вариант**.

Это **новый диагностический сбор WR/CK**, НЕ готовый додж этих способностей. Обычный `start.bat` оставлен как в alpha7: рабочие Counterspell, меню и ручной ввод не переделывались.

## По шагам

1. Распакуй полный архив **в новую папку**. Закрой ранее запущенный HACHBOB — консоль/оверлей. **Dota и демо оставь открытыми.** Не запускай `start.bat` параллельно сборщику.
2. Подготовь Anti-Mage и ещё одну цель, в которую выбранный противник может применить способность. Для первой части нужен Windranger, для второй Chaos Knight. Герои должны быть доступны наблюдению; не прячь их специально в туман. Это управляемый диагностический опыт, не требование к обычной игре.
3. Запусти **`TARGET_PROBE_CK.bat`** — это только последние три пункта списка ниже. Полный вариант **`TARGET_PROBE.bat`** оставлен для WR+CK:
   - WR: один полный Shackleshot в Anti-Mage;
   - WR: один полный Shackleshot в другого юнита;
   - WR: начать Shackleshot в Anti-Mage и отменить до вылета;
   - CK: один полный Chaos Bolt в Anti-Mage;
   - CK: один полный Chaos Bolt в другого юнита;
   - CK: начать Chaos Bolt в Anti-Mage и отменить до вылета.
4. **Перед каждым этапом** подготовь нужного героя, цель и готовую способность. Вернись в консоль, нажми Enter. Есть 5 секунд вернуться в игру, затем прогрев чтения и короткий звуковой сигнал, если системный звук доступен. Начнётся **10 секунд записи**: выполни только указанную попытку. Затем вернись в консоль к следующей подсказке. Не пытайся успеть всю последовательность за один таймер.
5. Между этапами можно восстановить CD. Во время записи не сбрасывай его и не включай No Cooldown: нужно отличить завершение от отмены. Если отменить быстрый Shackleshot не получилось, не называем это доказанной отменой — в архиве есть сырые фазы/CD, подписи этапов являются только твоими заявленными действиями.
6. После последнего этапа появится сообщение **«ПРИШЛИ ТОЛЬКО ЭТОТ ZIP»** и путь к файлу вида **`target_probe_20260929_… .zip`** в той же папке. **Пришли этот один ZIP.** Обычные `killsteal.log`, `overlay.log` и огромную копию консоли для этого теста присылать не нужно.

Если сборщик сообщил ошибку до начала записи, скопируй только текст ошибки. Если нужно остановить запись — Ctrl+C в его консоли: накопленные данные сохраняются с отметкой прерывания. У каждого запуска уникальное имя; прежний результат не перезаписывается.

## Почему ещё один сбор

Прежние логи уже установили: у WR поле цели невалидно, у CK известный заголовок нулевой. Они **не содержат** сырых данных приказов и структур эффектов. Повторение обычного теста не добавляет их задним числом.

Новый сбор пишет полные serial-bearing идентификаторы объектов, собственные поля WR со стартовыми/средними позициями стрел, текущие фазы/тайминги, контейнер приказов и счётчики контроллеров, заголовки эффектов героев и обнаруженные particle-entity поля. От именованных контейнеров разрешён один ограниченный переход по адресам-кандидатам. Это **не декодированный projectile manager**. Совпадение числа с handle — кандидат для анализа, а не доказанная цель. Контрольные точки/стрелочные поля не объявляются положением летящего снаряда без проверки.

Сборщик не нажимает клавиши, не блокирует ручной ввод, не меняет память игры, настройки или offsets. Он не подключён к автоматическому Dodger. Подписи «в AM / в другого / отмена» задаются человеком и не считаются автоматически проверенными.

## Ограничения и размер

- Только схема и PE-параметры уже используемой сборки; при несовпадении сбор останавливается. Автоматического переноса на любую архивную версию здесь нет.
- Целевой опрос 20 Гц; фактическая скорость измеряется. Поиск сущностей раз в 0.5 с и выборочная RTTI-проверка могут пропускать короткие эффекты.
- На именованный контейнер максимум два блока по 384 байта, один уровень перехода; полного сканирования памяти процесса нет.
- Потоковая запись с устранением повторяющихся сырых блоков: **12 МиБ JSONL на этап, максимум 72 МиБ на весь запуск**, исходный кадр — до 96 КиБ. Если этап достигает своего лимита, он сохраняется как неполный, но последующие этапы продолжаются со своим бюджетом. ZIP обычно намного меньше несжатого файла; размер зависит от данных. Словарь повторных блоков ограничен 4 МиБ символов; после заполнения новые блоки сохраняются напрямую, без потери данных.
- В кадрах отмечены неполнота, бюджет чтений, ошибки, проверки идентичности после чтения и время. Запись не доказывает цель/успешный dodge сама по себе.

Проверено офлайн: 26 тестов сборщика, из них 12 для FIX1; полная проверка 543 PASS / 1 SKIP (нет Mono). Твой исходный файл из 625 кадров перекодирован и полностью восстановлен без потерь: JSONL 25 161 393 → 15 660 818 байт, ZIP 268 208 байт. Это проверка формата, **не новый запуск в игре**. Дополнительно синтетическая проверка ёмкости: 6 × 400 кадров, без достижения лимитов. Windows/Dota-запуск FIX1 здесь не выполнялся; нативные C# и автоматизация byte-identical alpha7.

## Формат для анализа

Весь материал по-прежнему находится в двух файлах внутри результата: `frames.jsonl` и `manifest.json`. Формат v2 содержит определения `_raw_blobs` и ссылки `raw_ref` вместо повторяющихся длинных hex-строк. `collect_targets.iter_frames(lines)` восстанавливает исходные кадры и также читает старый v1. Ссылки не теряют исходные байты; порядок строк нужно сохранять. Предпочтительно прислать ZIP целиком. Если прикрепляются отдельные файлы, переименование `frames.jsonl` в `frames.json` допустимо: не редактируй содержимое и приложи `manifest.json`.
