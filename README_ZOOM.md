# HACHBOB Zoom — experimental 4 / исправление автоматического режима

**Исправлен отказ на значении −1.** Новый отчёт позволил разобрать код именно твоей сборки: `+0x2E4` используется как переопределение дистанции; отрицательное значение отправляет обычную ветку обновления к расчёту игры. Исходные −1 — не дистанция «минус один» и не доказательство неправильного адреса. Предыдущая проверка этого не учитывала.

Это уже версия для включения зума, **не очередной сборщик JSON**. Визуальный результат в живой Dota на стороне разработчика не проверен.

## Запуск

1. Закрой старое окно Zoom, распакуй этот архив в отдельную папку.
2. Войди в пробу обычного героя и запусти **`ZOOM.bat`**.
3. В заголовке должно быть **exp4**. При исходных −1 появится **«авто игры · OFF»**.
4. Нажми **«Включить зум»**. Начальное значение — 1500, ползунок 1000–2200.
5. **«Вернуть как было»** возвращает исходные байты: обычно **−1 / авто игры**, а не принудительные 1200.

End и обычное закрытие также пытаются вернуть исходное состояние. Если до включения уже было другое допустимое положительное значение, возвращается именно оно.

Нужен 64-битный Python 3.11 с tkinter, как раньше. Новых pip-пакетов нет. Никакие числа/адреса вручную вводить не нужно. `ZOOM_CHECK.bat` и `ZOOM_DETAILS.bat` для этого запуска не нужны и в новом архиве не предлагаются.

## Что изменилось

- Поле записи **не переносилось**: остаётся `+0x2E4`. Нет записи в `+0x270`, `+0x15C`, найденные числовым поиском поля или код.
- В наблюдавшейся обычной ветке обновления значение `+0x2E4 >= 0` передаётся в вычисляемую дистанцию `+0x15C`. При отрицательном значении игра рассчитывает её сама. `+0x15C` — результат, а не новая точка записи.
- Исходные **−1 разрешены только профилем с проверенным кодом**, не общей отменой проверки диапазона. 0, другие отрицательные значения, NaN/Infinity как исходный override не принимаются. Пользовательский ползунок по-прежнему ограничен 1000–2200.
- Перед управлением проверяются PE timestamp/размер, точное RTTI-имя, RVA vtable/менеджера/сигнатуры, указатель метода обновления и SHA256 всех 2840 байт наблюдавшегося метода. Проверка повторяется перед записями и при мониторинге.
- Если сборка или код отличаются, обычное окно **отказывает без fallback к старому непроверенному профилю**, даже если найдено число 1200.
- Положительный таймер перехода камеры `+0xDC` означает, что игра сама может менять override. В этот момент управление и восстановление останавливаются, чтобы не бороться с переходом.
- Надпись «задано 1500» показывает override, а не обещает, что любой специальный режим камеры уже применил его к изображению.

Основание исправления с адресами инструкций — `ZOOM_EXP4_ANALYSIS.md`.

## Ограничения

Остаются только дистанция камеры, явное включение и один 4-байтный параметр. Нет постоянного перезаписывания, автоматического включения после смены объекта, ZFar, тумана, погоды, DLL-патчей, записи в код, инжекта или удалённых вызовов.

Возврат разрешается только тому же объекту с тем же проверенным профилем и ожидаемыми нашими байтами. Чужое изменение не затирается. Переход камеры, изменение кода/объекта, остановка процесса могут сделать возврат невозможным. Проверки и запись не атомарны относительно игры; принудительное завершение Python не гарантирует восстановления. Ошибки возврата показываются отдельно. При оставшемся неверном масштабе перезапусти Dota.

Профиль привязан к присланной сборке (`1790705915`, размер `115027968`), а не ко всем будущим обновлениям. Специальные камеры могут использовать другую ветку расчёта. Совместимость, отсутствие гонок и античит-безопасность не гарантируются.

## Проверки

- **111 Zoom-тестов прошли**, включая **26 новых**: −1 → включение → слайдер → −1, положительное исходное значение, неизвестная сборка/код, переход камеры, чужая запись, End/закрытие и отсутствие постоянных записей.
- Старые синтетические worker-тесты явно подставляют старый тестовый locator. Новые worker-тесты проходят через настоящий новый проверяющий locator с синтетическим профилем.
- Полный набор: **1063 теста, 1060 пройдены, 3 пропущены** (необязательный Mono отсутствует).
- Реальное Tk-окно + worker проверены под виртуальным дисплеем с искусственной памятью: авто OFF → 1500 → 1750 → авто OFF → включение → закрытие с возвратом −1.
- **Win32 API и живая Dota на стороне разработчика не запускались.** Машинный код присланного отчёта разбирался офлайн, не исполнялся.
- 12 файлов принятого Last Hit/KS/ввода сверены с предыдущими архивами: без изменений. Их настройки не трогаются; блок крипов и Dodger остаются отложенными.

Исходники и лицензия MPL-2.0 включены. Происхождение — `zoom/NOTICE.md`, хеши — `zoom/MANIFEST.json`. Журнал — `zoom/zoom.log`. При оставшемся отказе достаточно текста из окна или журнала; новый диагностический запуск заранее не требуется.
