# HACHBOB · импорт и обновление патча

`patch_bundle.py` и `patch_update.py` работают **только с выбранными локальными JSON**. Они не скачивают offsets, не исполняют JSON, не находят произвольные адреса сами и не подтверждают совместимость с работающей игрой. Схема и смещения должны относиться к одному и тому же архивному клиенту.

## Обычный сценарий из меню

1. В меню открой **Настройки → «Импорт offsets…»**.
2. В одном диалоге отметь свежие `client_dll.json` и `offsets.json` (обязательны), при необходимости добавь `buttons.json` и `info.json`. Также принимается ZIP с этими файлами внутри. Путь через меню намеренно отказывает, если выбрано `ks_profiles.json` — каталог способностей ведёт разработчик.
3. Программа распознаёт JSON по именам, проверяет схему, обязательные offsets, диапазоны, дубли имён, SHA256 и профили. Неизвестные JSON перечисляются и игнорируются. Пакет только **ставится в очередь**; установочные файлы на этом шаге не меняются.
4. Закрой Dota, HACHBOB/feed и другие процессы Python. При следующем `start.bat` ожидающий пакет применится до запуска reader. Если проверка процессов/транзакция не проходит, запуск прекращается.
5. После импорта режим принудительно переводится в **PREVIEW** (`auto_cast=false`), а `live_modifier_layout` сбрасывается. Совместимость частного layout модификаторов нужно проверять отдельно; включать прежнее AUTO автоматически нельзя.

Кнопка **«Отменить ожидающий импорт»** удаляет только staged-пакет; установленные файлы не меняются. CLI-эквивалент:

```bat
py -3.11 patch_bundle.py --discard-staged
```

Импортёр не распаковывает ZIP-пути в файловую систему: он читает ограниченный набор имён в память, сверяет квитанцию SHA256 и проверяет файлы повторно перед применением.

### Что означает каждый JSON

- `client_dll.json` — публичные поля классов/сущностей; сопоставляются по точным парам «класс / поле».
- `offsets.json` — поддерживается стандартная схема с группами `client.dll` и `engine2.dll`. Известные globals/object offsets адаптируются в проверяемый внутренний manifest. Остальные поля не угадываются.
- `ks_profiles.json` — не принимается обычным меню, чтобы пользовательский импорт не менял каталог способностей. У разработчика остаётся отдельный CLI-путь для проверки подготовленного релизного профиля; перед применением AUTO принудительно выключается, private modifier layout очищается.
- `buttons.json` — распознаётся, валидируется и хранится внутри `.patch_staging` как справочный файл. Его action offsets **не являются биндами клавиатуры** и сейчас не используются HACHBOB; пользовательские кнопки остаются в профилях.
- `info.json` — метаданные дампа. Его `build_number` не используется вместо `engine2.dll.dwBuildNumber`.

На приложенном к текущей сессии комплекте `offsets.json` содержит `dwBuildNumber=6356260`, тогда как `info.json` содержит `build_number=48`. Проверка использует значение из `offsets.json`; `info.json` — только метаданные дампа. В приложенной паре `client_dll.json` совпал с текущим файлом по SHA256 и mapped constants изменений не дали. `buttons.json` был корректно распознан, но не назначен биндам.

## Что автоматизировано

- Сопоставление 71 публичного поля по точным именам.
- Проверка обязательных ключей, типов/диапазонов, повторяющихся JSON-ключей, SHA256 схемы и синтаксиса Python.
- Резервные копии трёх файлов, атомарная замена каждого, receipt с хешами, lock-файл и откат. Несколько файлов не заменяются одной filesystem-транзакцией; незавершённую операцию блокирует `.patch_pending`.
- При применении через updater всегда задаётся PREVIEW и удаляется approval локального private modifier layout. Ни один импорт не подтверждает адреса в работающей игре.

## Ручная проверка/применение

Для внутреннего `hachbob-offsets-v1` manifest сначала можно посмотреть текущие значения (это **старые** значения, не новый патч):

```bat
py -3.11 patch_update.py --template old_globals.json
```

Сопоставление схемы без записи:

```bat
py -3.11 patch_update.py --schema new_client_dll.json
```

Если для выбранных файлов подготовлен проверенный `new_globals.json`, запусти dry-run и затем — только после проверки diff и закрытия Dota/HACHBOB/feed/других Python — явное применение:

```bat
py -3.11 patch_update.py --schema new_client_dll.json --globals new_globals.json
py -3.11 patch_update.py --schema new_client_dll.json --globals new_globals.json --apply
```

Опциональный профильный JSON можно проверить/применить вместе:

```bat
py -3.11 patch_update.py --schema new_client_dll.json --globals new_globals.json --profiles new_ks_profiles.json
py -3.11 patch_update.py --schema new_client_dll.json --globals new_globals.json --profiles new_ks_profiles.json --apply
```

Не копируй новый `client_dll.json` поверх установленного до создания backup: иначе старая схема не попадёт в резервную копию. Инструмент показывает путь к бэкапу и команду отката:

```bat
py -3.11 patch_update.py --rollback ".patch_backups\YYYYMMDD-HHMMSS-XXXXXXXX"
```

Откат сверяет receipt и откажется затирать файлы, изменённые после применения. Если появился `.patch_pending`, не удаляй его вручную: используй напечатанный путь backup и `--rollback`. При повреждённом/неполном backup восстанови отдельную целую копию установки; не запускай feed в обход lock.

## Не обновляется автоматически

- Внутренние структуры entity-system/vector, particle/projectile manager и private modifier layout.
- Таблицы урона, таланты, радиусы каста, тип/размер полей, усиление предметами, Scepter/Shard и защита.
- `buttons.json` не конвертируется в бинды; `info.json` не подтверждает engine offsets.

После любого импорта сначала проверяй **PREVIEW**. Совпадение имени поля, SHA схемы и числового диапазона — это структурная проверка, не доказательство правильности смещения/модели для текущего клиента.
