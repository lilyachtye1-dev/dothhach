# Last Hit alpha4 · новый путь обнаружения и отдельный Helper

**Полный комплект.** Закрой старую версию, распакуй в новую папку, запусти `start.bat`.

Настройки как в alpha3: **Quick Attack ВЫКЛ, автоатака «Никогда», атака A, Stop S**, выбран свой герой. Включение — Insert → Скрипты → Last Hit. По умолчанию автоматизация работает при удержании **Mouse4**; есть режим переключения нажатием.

**Подсветка прочитанных крипов теперь появляется без удержания.** Мечник, дальний, знаменосец и катапульта имеют подписи HP / расчётный урон. Серый означает дальность, а не отсутствие обнаружения. Есть отдельный режим «Только помощник» без ввода.

Безусловная ручная пауза alpha3 убрана: теперь это опция, по умолчанию выключенная. Обнаружение использует полную ограниченную таблицу entity; target-reader не требует параметров собственной атаки крипа. Добавлены счётчики обнаружения, дальности, готовности и ошибок вместо одной общей причины.

Скорость атаки дополнена живыми значениями поддержанных модификаторов Treads/Phase/Wraith Band и текущей ловкостью. У катапульты отдельно читается модификатор входящего урона героя. **Это частичная модель с пока не проверенными в живом запуске новыми полями, не обещание точности Umbrella.** При неизвестном уроне катапульта видна, но автоматически не атакуется.

Текущая инструкция, режимы и ограничения: **[LAST_HIT_ALPHA4.md](LAST_HIT_ALPHA4.md)**. Offline-проверки: `test-results.txt`. Windows/Dota alpha4 здесь не запускалась. Ниже — история, не текущие настройки.

# Last Hit alpha3 · прицельный клик, своя атака → Stop

**Полный комплект.** Закрой старый HACHBOB → распакуй в новую папку → `start.bat`.

**После alpha2 поменяй настройки Dota:** Quick Attack **ВЫКЛ**, автоатака **«Никогда»**, атака **A**, Stop **S**. Выдели своего героя. Включи Last Hit через Insert → Скрипты → Last Hit, закрой меню и удерживай **Mouse4**.

- По врагу — прицельный ПКМ, для деная — обычный A+ЛКМ. Точка внутри модели, не у ног. Это не внутренний AttackTarget и не второй независимый курсор.
- «Одна атака» по умолчанию: Stop только после своей наблюдаемой атаки/расчётного замаха, пока нет ручного вмешательства, каста или KS/Dodger. При отпускании отложенный Stop отменяется. Гарантии ровно одного попадания нет: фазу атаки ещё нельзя считать доказанной.
- На плашке — мой урон min–max, броня крипа и нижний расчёт по цели. Добавлен регулируемый запас 8%; он не подменяет живые статы и может делать выбор осторожнее.
- Исчезновение цели до подтверждения не выключает весь модуль. Реальная ошибка ввода/длительное отсутствие подтверждения при доступной цели по-прежнему останавливают отправку.

**Новая версия в Windows/Dota здесь не запускалась.** Прогноз башни/урона приблизительный; не все модификаторы учитываются. Самостоятельной погони/маршрута нет. Подробнее: **[LAST_HIT_ALPHA3.md](LAST_HIT_ALPHA3.md)**, общая инструкция: `LAST_HIT.md`, проверки: `test-results.txt`.

Камера удалена, KS/Dodger не расширялись. Далее — история выпусков; старые указания Quick Attack ON не являются настройкой по умолчанию для alpha3.

# KS input FIX · без камеры

**Обычный запуск: `start.bat` → Insert → Killsteal → кнопка включения.** Полный комплект; распаковать в новую папку, не поверх старой версии. Камера и её worker удалены из этой сборки.

- Enter/Tab больше не выключают KS. Пока клавиша удерживается, отправки нет; после отпускания не нужно снова включать модуль.
- Убрана общая пауза KS от мыши, Alt/Shift/Ctrl и других игровых клавиш. Изменена не только проверка сервиса, но и настоящий путь SendInput: используется общий приоритетный sender с восстановлением физических модификаторов.
- Удерживаемая клавиша самого выбранного каста не дублируется. Занятость героя, валидность цели, CD, геометрия, фокус и свежесть остаются проверками.
- Выключенный Dodger сообщает OFF один раз, без периодического reader/trace-спама. Ошибки и подтверждения уже отправленных действий не скрываются. Детекторы и возможности Dodger не расширялись.

**Чат автоматически не определяется. После отпускания Enter KS снова может отправлять ввод: перед перепиской выключай KS кнопкой.** Сохранение ON не является распознаванием закрытого чата. End — выход; Insert — меню без сброса включения.

Подробности: `KS_INPUT_FIX.md`. Ниже — история старых выпусков и общая документация. Старые описания пауз KS заменены этим выпуском; повторные записи CK/WR не нужны.

# Alpha 7 · ручные касты: точечное исправление потери угрозы

Распакуй **в новую папку**, запусти `start.bat`. Нативное меню и настройки alpha6 не изменены; Insert сохраняет ON/OFF.

- **Blink во время каста Sniper** больше не удаляет уже установленную связь с угрозой автоматически. Принудительно перечитывается метка; нужны тот же экземпляр, герой/кастер/способность и непрерывная фаза. Интервал пересчитывается по новой позиции. После вылета скачок позиции по-прежнему отменяет старую оценку полёта.
- **Ручные способности и предметы вне списка профилей:** подтверждение их активного каста теперь передаётся непосредственно из reader. Они не объявляются неизвестной занятостью только потому, что отсутствуют среди источников KS/Dodger. Действительно неизвестное чтение не разрешает принудительный ввод.
- **Краткое изменение списка эффектов при чтении:** уже отслеживаемая фаза может пережить повторную проверку в пределах прежних 150 мс. Пока свежей метки нет — нажатий нет. Смена владельца/экземпляра, чужая цель, длинный пропуск и неизвестность после запуска не обходятся.
- В журнале теперь различаются **потеря отслеживания → отказ до ввода → отправка → CD/нет CD**, с конкретными причинами и состоянием ручных игровых клавиш в момент угрозы.

Это исправления воспроизводимых ошибок кода, **не доказательство причины каждого пропуска в твоём логе**. Блокировки физической клавиатуры, Stop/F1 и повторного спама E не добавлено. Конкуренция команд внутри игры пока не объявляется полностью решённой. **Chaos Bolt остаётся только диагностикой.**

Проверка: **517 тестов прошли, 1 пропущен без Mono; 23 новых теста прошли**. Исходники C# не менялись относительно alpha6. В Windows/Dota alpha7 здесь не запускалась. Детали: `research/alpha7_findings.md`, `test-results.txt`.

### Alpha 6 · приоритет защиты и Insert без выключения

Основа прежняя: **lilyachtye1-dev/dothhach**, commit `8739838`. Распакуй **в новую папку**, не смешивай файлы с alpha5. Запуск `start.bat`; отдельная страница **Скрипты → Dodger** сохранена.

- **Мышь и обычные клавиши больше не ставят Dodger на ручную паузу — для всех доступных защит, не только E.** Shift/Ctrl/Alt временно нейтрализуются с отслеживанием физического состояния. Известный ваш каст может быть прерван ради защиты. Удерживаемая собственная клавиша защиты не нажимается повторно; Win, игровой Enter/Tab/End, неизвестная занятость, плохие данные/фокус остаются ограничениями. Один общий sender, без параллельных нажатий; в этом историческом выпуске политика KS не менялась; актуальные изменения KS описаны в начале README.
- **Insert сохраняет ON/OFF обоих модулей.** В открытом меню ввод приостановлен. Закрытие возобновляет ранее включённые модули после возврата в Dota и проверки свежих данных. Явные кнопки OFF и аварийные остановки остаются. Само открытие меню ничего не включает и не сбрасывает quarantine.
- **Ближний Assassinate:** Counterspell может сработать до вылета по подтверждённой локальной метке, наблюдаемому касту и оценке его окончания. Неизвестный cast point допускает калибровку после двух согласованных завершённых кастов при непрерывном наблюдении. Это прогноз, а не гарантия: отменённый каст Sniper может потратить E. Для Manta/дизджойнта предзапуск не разрешён.
- **Lotus/Eul/Wind Waker по умолчанию работают через прежнее наведение на себя.** Опция `Alt self-cast` убирает движение курсора только при подходящих настройках игры: сначала проверь вручную Alt+слот / Smart Double Tap. Опция выключена по умолчанию; разрешены только буквы/цифры, не Alt+F4 и не numpad.
- **Chaos Bolt пока НЕ запускает защиту.** Добавлена диагностика фазы и поля `hAlreadyHitList`, но доказанной будущей цели в этой схеме нет. Это не готовая поддержка CK и не реакция на любого ближайшего кастера. Для следующего исследования нужен новый лог с несколькими Chaos Bolt.

По твоему alpha5-логу: **15 отправок и 15 подтверждений CD** (12 Counterspell, 2 Manta, 1 Lotus), без quarantine. Пять близких запусков оставляли меньше бюджета ввода — поэтому добавлен предзапуск, а не просто ускорено повторное нажатие.

**Проверки:** 495 автоматических теста, включая 65 новых; C#5/.NET 4.8/x64 собирается с warnings-as-errors. **В Windows/Dota alpha6 здесь не запускалась**, физический hook и реальное отражение требуют проверки в игре. `SENT`/CD не доказывают успешный dodge. Выбранным юнитом должен оставаться свой герой; игровой чат/магазин и выделение юнита не декодированы.

Подробности и ограничения: `DODGER.md`, `research/alpha6_findings.md`, `test-results.txt`. Ниже сохранена история базовых функций; актуальные правила ввода и меню — alpha6.

# HACHBOB · 5.2

Тот же тёмно-фиолетовый интерфейс, теперь с названием **HACHBOB**. Запуск — `start.bat`, меню — **Insert**; Killsteal включается только кнопкой в окне программы. **F6 не переключает Killsteal**, а Esc не выключает и не приостанавливает его. Lotus отражает заклинание, но не является универсальным отменителем попадания. Для разных защит нужны разные правила. Фаза каста врага не доказывает, что он атакует тебя; старая позиция героя не доказывает его нынешнее положение в лесу. Поэтому фиктивных включателей этих функций здесь нет.

### Сборщик для следующих двух модулей

`COLLECT_EVENTS.bat` / `collect_events.py` — **диагностика, не автододж**. Не нажимает клавиши, не двигает курсор, не пишет в память игры. Сэмплирует RTTI/поля particle-entity и непрозрачные заголовки `m_Particles`, фазы каста и координаты с пометкой о возможной устарелости. Непроверенные контейнеры не разыменовывает.

Если нужно продолжить эти модули: закрой обычный HACHBOB/feed, в демо запусти `COLLECT_EVENTS.bat`, за 5 секунд вернись в игру и за следующие 15 секунд воспроизведи **один** снаряд (например, Storm Bolt) либо нужный эффект молнии. Сохраняется `event_probe.zip`; его можно прислать вместе с названием события. Для второго эпизода переименуй первый архив или используй `--output другое_имя.zip`. Это новый сбор событий, повторять тесты инвентаря/трёх убийств Finger не нужно.

Сборщик экспериментальный: короткие эффекты могут быть пропущены, нужного эффекта может не быть в entity system вообще. Пустой результат не доказывает отсутствие партиклов и не гарантирует, что этого сбора будет достаточно для реализации.

**Проверки этой офлайн-сборки:** `test-results.txt` фиксирует Python-проверки. Новое WPF-меню и drag-and-drop HUD в этой среде не запускались; сборка на Windows и проверка в Dota остаются обязательными.

# HACHBOB / KS5 — меню и живой список источников

Тёмная панель с фиолетовыми акцентами, вдохновлённая присланными примерами. Это **собственный интерфейс**, не Octarine. В сборке есть **настоящее WPF-меню**, связанное с Python-reader, а не только HTML-макет.

## Запуск и управление

1. Закрой предыдущий оверлей через **End** и его консоль. Распакуй архив **в новую папку**.
2. Используй **quickcast на нажатие**. Каталог профилей и бинды поставляются разработчиком; пользовательский редактор в приложении отключён.
3. Запусти **`start.bat`**. Меню откроется автоматически; герой и источники появятся, когда reader их прочитает.
4. **Insert** — показать / скрыть меню; **End** закрывает программу. **F6 не переключает Killsteal.** Esc не меняет его состояние.
5. Открытие меню приостанавливает ввод, сохраняя включённое состояние Killsteal. На главной странице нажми **«Включить Killsteal»**: меню закроется, а сервис включит его только после возврата фокуса в Dota и проверки свежих данных/живого героя. При смерти включённое состояние сохраняется на паузе и продолжает работу после возрождения. Короткая потеря данных сначала только приостанавливает действия; длительная потеря по-прежнему безопасно выключает их.

Это отдельное прозрачное WPF-окно-оверлей, а не встройка в интерфейс игры. Плашки HP/способностей берут текущие экранные координаты героев без дополнительного сглаживания, чтобы не оставлять видимый хвост за движущейся моделью; они обрезаются по клиентской области Dota и не рисуются поверх заголовков/соседних окон. Нижняя панель работает независимо от них, закреплена относительно клиентской области и не следует за моделями героев или камерой. Небольшая задержка самого reader/отрисовки всё ещё возможна. В эксклюзивном полноэкранном режиме открытие меню может свернуть игру; предпочтителен **оконный режим без рамки**. Меню можно перемещать за верхнюю полосу и менять его размер. Кнопки разделов теперь переключают/прокручивают нужные настройки; наведение и нажатие дают плавный визуальный отклик. Пока Dota не в фокусе, игровые плашки и компактный статус скрыты.

Windows / Python 3.11 x64 + pymem / .NET Framework 4.8 — требования прежние. Дополнительных pip-пакетов для меню нет. Сборка C# теперь включает `ks_menu.cs` и стандартную библиотеку `System.Web.Extensions`.

## Разделы меню

- **Скрипты → Killsteal:** текущий локальный герой, HP/мана, состояние AUTO, поддерживаемые способности и предметы (включая Dagon при наличии в активном слоте). Все источники читаются автоматически.
- **Настройки героев:** верхняя сетка содержит только героев с активными профилями в скрипте. Нажми портрет и включи нужные поддерживаемые способности. Это лишь сессионная конфигурация: runtime по-прежнему сверяет профиль с фактическим локальным героем из игры.
- **Визуал:** отдельно включаются плашки HP/способностей над героями и нижняя фиксированная панель с портретами, HP и способностями (с перезарядкой/уровнем) **до пяти текущих видимых врагов**; оба элемента можно показывать одновременно. Плашки используют текущую экранную позицию без сглаживания и показываются, только пока герой внутри клиентской области окна Dota; рендер обрезан её границами. Это убирает дополнительное отставание, создаваемое самим оверлеем, но не устраняет возможную задержку фида/кадра. Панель заякорена к окну, а не к камере/моделям. Скрытые туманом, отсутствующие в текущем фиде и просроченные данные не показываются. Для перемещения панели/ряда портретов включи «Режим размещения», закрой меню через Insert и перетащи HUD. Это стилизованный WPF-оверлей, не внутриигровая встройка. Сброс возвращает нижнюю панель вниз по центру.
- **Настройки:** только общие функции, reader-статус, журналы и проверенный импорт комплекта offsets. Пользовательское изменение/добавление профилей через меню не предусмотрено; импорт `ks_profiles.json` из меню запрещён.

**«Готов» означает готовность ресурсов и известной модели, а не гарантию убийства.** Дальность до конкретной цели, HP, защита и финальные проверки ввода остаются в движке. Открытие меню сохраняет состояние Killsteal; после закрытия он возобновляется при допустимых данных и фокусе. F6 не включает и не выключает Killsteal. Профиль в меню можно только включить/выключить на эту сессию.

## Переключатели источников

Переключатель справа включает/выключает **профиль на текущую сессию**. Для Dagon это весь профиль со всеми его вариантами. После смены героя настройки других профилей сохраняются до перезапуска, но чужой герой/неизвестные бинды не допускаются движком.

- Изменение выключает AUTO; **повторное включение профиля не включает AUTO**.
- Ожидание CD и карантин после неподтверждённого ввода не сбрасываются переключателем.
- После перезапуска используются определения из каталога, поставленного разработчиком. В пользовательском интерфейсе нет создания/редактирования профилей; сессионные переключатели не переписывают `ks_profiles.json`.
- `ui_session_controls.json` — автоматически создаваемый локальный файл команд, **не второй файл способностей**. Команды имеют токен сессии и возрастающий номер; старые команды после перезапуска игнорируются. Вручную его редактировать не нужно.

Настройки внешнего вида сохраняются в `overlay_visual.json`. **F7** переключает показ локального героя, **F8** — фильтр врагов. Изменения настроек/профилей не включают AUTO.

## Расчёт Finger, сохранённый из 4.2

**Повторять тест с убийствами не нужно.** По двум сериям снимков подтверждено расположение счётчика: поле `int32 +0x84` объекта `CDOTA_Modifier_Lion_FingerOfDeath_Kill_Counter`. В новой чистой серии без предметов снова прочитано **1 → 2 → 3**. Адрес героя и адрес счётчика между сериями изменились — фиксированные адреса из снимков в код не перенесены.

Теперь reader на каждом кадре находит счётчик в текущем списке модификаторов и передаёт количество стаков в расчёт. Формула Finger:

```text
урон до защиты = база по уровню ульты + стаки × (25 + бонус таланта)
бонус таланта = 20, если соответствующий талант изучен, иначе 0
магический урон по цели = урон до защиты × (1 − оценка MR цели)
```

**25 и 20 — значения, сообщённые пользователем для его игры**, а не величины, извлечённые из памяти. Число стаков и уровень изучения таланта читаются из игры. Три стака дают **+75** до таланта или **+135** с талантом, до защиты цели. Просто достижение 20-го уровня не включает бонус автоматически.

Привязка таланта: `special_bonus_unique_lion_8`, читается его собственный `m_iLevel` (0/1). Имя сопоставлено с описанием `+20 Finger of Death Damage Per Kill` в [OpenDota dotaconstants](https://raw.githubusercontent.com/odota/dotaconstants/master/build/abilities.json). Класс есть в приложенной схеме. **В присланных снимках талантов нет**, поэтому смысл этого имени для архивной сборки отдельно не подтверждён снимками; это редактируемая привязка в профиле, а не доказательство соответствия всех данных текущему патчу. Если нужная сущность не найдена или прочитана ненадёжно, бонус не угадывается.

На панели всегда показываются **стаки** и состояние **таланта +20**. `?` означает неизвестное, не ноль. Если неизвестно число стаков, Finger не используется. Если число стаков известно, но талант нет, рассчитывается только нижняя оценка `база + стаки × 25` без бонуса таланта: Finger может сработать лишь когда этой оценки хватает; если добивание возможно только с неподтверждённым бонусом, каст откладывается. Карточка явно помечает такую оценку. Другие доступные способности продолжают оцениваться. Ноль при отсутствии модификатора принимается только после успешной проверки всего списка.

### Что сохранено

- Глобалки работают без экранной точки врага; камера не должна смотреть на цель. Для `no_target` проверяется мировой радиус, но не проекция. Для `unit`/`point` экранная точка нужна.
- Проверки dormant/FOW и свежести кадра, quickcast **на нажатие**, включение Killsteal кнопкой программы, ожидание CD и следующие автоматические попытки.
- Проверенный inline-декодер инвентаря FIX3, один файл настройки **`ks_profiles.json`**.

### Что НЕ заявляется решённым

- **Усиление заклинаний предметами пока не включено.** Тест без предметов не подтверждает правила усиления/переключения Rapier, суммирование эффектов и другие модификаторы.
- **Базовая дальность и урон по уровням берутся из `ks_profiles.json`.** Текущие 650 для Impale взяты из публичного snapshot 7.41f, не из offsets; это не runtime-измерение cast range. `m_flRangeDisplayDist` не используется как универсальная дальность каста.
- Scepter/Shard, остальные таланты, барьеры, модификаторы входящего урона и полная модель MR по-прежнему не реализованы. Это не точный универсальный симулятор урона.

### Как устроено чтение стаков

Используется прямой ограниченный список: менеджер у героя по schema `m_ModifierManager`; его owner `+0x08`, count `+0x10`, pointer `+0x18`, capacity `+0x20`. У объектов проверяется обратная ссылка на менеджер `+0x30` и runtime RTTI. Заголовок, указатели, типы, владельцы и число стаков перечитываются для обнаружения изменений во время чтения. Не используется широкое сканирование соседней памяти в боевом цикле.

Чтение разрешено для PE timestamp **1790374954**, SizeOfImage **115027968** и SHA-256 приложенной схемы. Эти метаданные — проверка совместимости, **не криптографическое доказательство версии исполняемого файла**. При несовпадении, неизвестном типе модификатора или неполных чтениях счётчик считается неизвестным. Не меняй эти ограничения вслепую.

Добавлена одинаково оформленная необязательная секция профиля:

```json
"stack_scaling": {
  "modifier": "CDOTA_Modifier_Lion_FingerOfDeath_Kill_Counter",
  "per_stack": 25,
  "talent": "special_bonus_unique_lion_8",
  "talent_bonus": 20
}
```

Она включена только у Finger. Все коэффициенты и привязки остаются в **одном `ks_profiles.json`**; `settings.live_modifier_layout` содержит проверяемую конфигурацию чтения. Для произвольного другого модификатора такой же смысл полей не гарантируется.

`COLLECT_LIVE.bat` оставлен как необязательный диагностический инструмент, для обычного запуска он **не нужен**. Его широкие поисковые находки не подключаются к автокасту автоматически. В KS5 сохранён отдельно проверенный прямой reader из 4.2.

## Как запустить

Из работающей **4.2 можно перенести свой `ks_profiles.json`**: формат профилей в KS5 не менялся. Из 4.1 и более ранних версий целиком переносить его не следует — там нет конфигурации live-стаков; перенеси только нужные бинды.

1. Закрой старую версию: **End**, затем закрой её консоль. Распакуй KS5 **в новую папку**, не смешивай файлы со старой сборкой.
2. **В игре включи quickcast НА НАЖАТИЕ клавиши** для нужных способностей и предметов. Это изменение относительно FIX3: обычный R + клик больше НЕ используется.
3. Проверь бинды: профили рассчитаны на обычные **Q/W/E/R**, предметные слоты 0–5 — **Z/X/C/V/B/N**. Если твои клавиши другие, поменяй их в **`ks_profiles.json`**. Неизменность раскладки не определяется автоматически.
4. Запусти **`start.bat`**. Выбери своего героя в игре. Сразу после запуска всегда **OFF**.
5. Нажми кнопку **«Включить Killsteal»** на главной странице. Меню закроется; включение произойдёт только после возврата фокуса и проверок состояния. Теперь модуль сам ищет добиваемые цели, наводит курсор там, где это нужно, и нажимает quickcast-клавишу. **F6 не переключает Killsteal.**
6. Esc не меняет состояние Killsteal; **End → выход**. При смерти Killsteal приостанавливается и возобновляется после возрождения, если он был включён до смерти.

Обычный запуск не требует ввода YES и не ограничен Lion. Тест проходить не нужно. `PREVIEW.bat` — необязательный режим подсказок без отправки ввода.

Требования прежние: Windows, Python 3.11 x64 + pymem, .NET Framework 4.8. `start.bat` проверяет конфигурацию и собирает C#-оверлей. Если уже работал FIX3, новые зависимости не нужны.

**Важно про цифры:** профили обновлены по публичным данным Dota 2 7.41f из OpenDota/Dotaconstants commit `bf193a5` от 19.09.2026. Это ближайший найденный набор к присланным offsets (время клиентской схемы — 26.09.2026), но `dwBuildNumber=6356260` не удалось независимо привязать к 7.41f. Числа не извлечены из запущенной игры; новые шаблоны выключены. Перед включением сверь версию, quickcast-бинды, дальность и тип каста. Отдельная ведомость — `ABILITY_CATALOG_RU.md`. Запуск всегда OFF; для PREVIEW также нет отправки ввода.

## Что изменилось

- **Только quickcast:** отправляются key-down/key-up; автоматических кликов ЛКМ больше нет. Для `unit`/`point` курсор перемещается; для `no_target`/`global` — нет.
- Killsteal включается **только кнопкой в программе**. F6 не включает и не выключает его.
- **Обновлено в KS input FIX:** ручные ЛКМ/ПКМ и чужие клавиши способностей/предметов больше не ставят KS на общую паузу. Shift/Ctrl/Alt нейтрализуются на время короткой отправки и восстанавливаются по физическому состоянию. Собственная удерживаемая клавиша выбранного каста не дублируется; известный каст/канал героя не прерывается. Курсор может перемещаться при прицельном касте.
- **Потеря фокуса вне меню приложения, смена локального героя или отсутствие пригодных данных/геометрии дольше 2 с → OFF. Enter/Tab сохраняют ON; отправка задерживается только пока клавиша удерживается.** Esc не выключает и не приостанавливает Killsteal. Смерть не стирает включённое состояние: действие приостанавливается до возрождения и проходит повторные проверки безопасности. Меню приложения временно приостанавливает ввод без сброса ON/OFF. Enter/Tab внутри подтверждённого нативного меню не считаются игровым hard stop.
- После отправки ждём наблюдаемого изменения **CD** (либо уменьшения зарядов у профилей с `requires_charges`). Затем выдерживается интервал/ожидаемое время попадания и снова выбирается цель — без повторного нажатия кнопки.
- Если CD не изменился за отведённое время, этот источник блокируется от повторов до наблюдения CD>0. Это предотвращает бесконечный спам клавишей при неправильном биндинге, обычном касте вместо quickcast или отклонении ввода. Повторное нажатие кнопки не снимает такую блокировку. Сначала исправь причину; реальное наблюдение CD или перезапуск сбросит соответствующее состояние.
- **SENT означает вставку клавиатурного ввода, не подтверждённое убийство.** Даже наблюдение CD не доказывает попадание/убийство.
- Исправление inline-инвентаря `count + handles` из FIX3 сохранено. Dagon определяется по реально прочитанному предмету и текущему основному слоту; алиас `item_dagon_upgraded` использует прочитанный уровень. Исправление подтверждено пользователем на его архивной сборке. Stash/backpack не используются для каста.

## Каталог способностей

`ks_profiles.json` — внутренний каталог профилей, который поддерживает разработчик. В приложении пользователь может выбрать героя из списка поддерживаемых и включать/выключать существующие источники только на текущую сессию. Создание, добавление или редактирование способностей/предметов и импорт пользовательского файла профилей через меню отключены. Новые записи доступны только в поставляемом обновлении.

Базовый урон, дальности и тип каста берутся из профилей разработчика; offsets сами по себе эти параметры не содержат. Данные публичного snapshot 7.41f и ограничения конкретных шаблонов описаны в `ABILITY_CATALOG_RU.md`; это не подтверждение совпадения с клиентом пользователя.

## Что есть в комплекте

**29 включённых профилей: 28 способностей и один профиль Dagon 1–5; сейчас поддерживается 22 героя.** Это набор распространённых нюков, а не поддержка всех способностей Dota.

- Lion: Finger, Earth Spike.
- Zeus: Arc Lightning, Lightning Bolt, Wrath.
- Lina: Dragon Slave, Light Strike Array, Laguna Blade.
- Venge: Magic Missile, Wave of Terror.
- Lich, Ogre, Sven, Bane: основные направленные нюки.
- Pugna, Crystal Maiden, Leshrac: наземные взрывы/станы.
- Queen of Pain, Necrophos, Centaur: ближайшая цель в радиусе no-target нюка.
- Luna, Rubick, Shadow Shaman, Tinker, Skywrath Mage: соответствующие направленные нюки.
- Dragon Knight, Death Prophet, Magnus: point-направление на текущую позицию цели. Puck пока не включён: для Orb нужен vector drag/release.
- Dagon: уровни и клавиши текущих активных слотов.

Для наземных/линейных `point`-кастов по умолчанию нужна история не менее 0.3 с со скоростью не более 40 world units/s. Упреждение, полный hit-test траектории, хитбоксы и будущая смена направления не моделируются. Даже неподвижная сейчас цель может уйти до попадания.

**5 отключённых шаблонов:** Sun Strike, Reaper's Scythe, Culling Blade, Powershot, Burrowstrike. У них зависимость от других уровней/недостающего HP, правила казни, зарядка/канал либо перемещение своего героя. Эти механики нельзя честно заменить обычным фиксированным уроном. Для них потребуется отдельная реализация модели, а не включение флажка.

## Ограничения

- Ограничения MR и неполной модели игровой видимости сохраняются; зависимость видимости от проекции убрана. MR приблизительный; есть счётчик Finger и указанная привязка его таланта, но нет полной модели остальных талантов, Scepter/Shard, amplification, барьеров, внешних аур и временных защит. Маски состояния по умолчанию нулевые — **это не распознавание stun/silence/иммунитета**.
- AUTO по цели с неизвестным инвентарём не разрешается. PREVIEW может показать оценку без предметных бонусов с предупреждением. Владельцы заданных защитных предметов исключаются консервативно.
- Глобальные профили выбирают живых наблюдаемых врагов независимо от экрана; неизвестная видимость запрещает выбор. Свежесть чтения памяти не гарантирует, что игра обновляет все сетевые поля — поведение dormant/FOW в этой сборке нужно проверить в игре.
- Механика «урон по недостающему HP», казнь, сложные DoT, случайные отскоки, Multicast, канал и физический урон не реализованы этими flat-профилями. У Ogre учитывается только один Fireblast.
- Выбранный игроком юнит отдельно не определяется: перед включением выбери своего героя. Украденные/нестандартно назначенные способности не получают автоматические бинды.
- Чат/игровые меню не распознаются. Enter/Tab больше не выключают ON: после отпускания KS может продолжить ввод, даже если чат остался открыт. Перед перепиской выключай KS кнопкой. Esc намеренно не меняет состояние Killsteal. Меню приложения приостанавливает ввод, но не выключает модуль; Enter/Tab не снимают включённое состояние KS. F6 не переключает Killsteal и может доходить до игры как обычная клавиша.
- Нет инъекции, записи в память и обхода античита. Обычный SendInput может быть отклонён. Фокус и ввод нельзя сделать атомарными. Гарантии отсутствия блокировки аккаунта нет.
- Схемы из Explorer и `client_dll.json` не смешиваются; используется согласованная с рабочим FIX3 схема. Глобальные адреса не обновлялись. Список способностей исходного reader расширен с ограничения 7 до доступных 32 записей вектора.

## Проверки и диагностика

Для зависаний в матчах 5×5 добавлены лёгкие замеры по отдельным этапам. В консоли строка `[perf] reader` показывает общий цикл, быстрый опрос и длительность `snapshot()`; `[perf] sender` показывает задержку цикла UDP/сервиса. В `overlay.log` строки `SLOW UI TICK` и `SLOW RENDER` разделяют задержку диспетчера WPF и собственно отрисовки. Причина прежнего зависания пока не подтверждена: эти метрики нужны, чтобы определить, где именно теряется ~1,5 секунды. Python + WPF/C# оставлен без переписывания до профилирования.

Если пауза повторится, сохрани время эпизода и приложи `killsteal.log`, `overlay.log` и строки `[perf]` из окна консоли — это позволит сопоставить остановку feed, UI и Killsteal. Замеры не отменяют безопасную остановку при длительном отсутствии свежих данных.

Тесты этой версии указаны в `test-results.txt`; добавлены проверки списка поддерживаемых героев, запрета импорта пользовательского `ks_profiles.json` через меню, безопасной кнопки включения, паузы при смерти, FOW-фильтра и независимости двух HUD-элементов на статических контрактах. Новые изменения всё ещё требуют проверки в Windows/Dota.

Базовый V5 ранее проходил кросс-компиляцию C# 5 / WPF с reference assemblies .NET Framework 4.8 без ошибок и предупреждений. После переименования в HACHBOB здесь повторная нативная компиляция не выполнялась. Повторно проверены Python-синтаксис и тесты, включая отсутствие проекции у global/no_target, реальный dormant/нечитаемый флаг, ложный FOW при движении камеры, ограниченный RTTI-поиск и сравнение снимков счётчика. Добавлены воспроизведение трёх реальных списков модификаторов без предметов, чтение обновившегося счётчика, владельцы, смена сборки/схемы, изменения во время чтения, выбор таланта и формула 25/45. При воспроизведении снимков RTTI заменён сохранёнными метками классов; сам RTTI-декодер имеет отдельные синтетические тесты. Windows/Dota здесь недоступны.

**Эта новая версия здесь не запускалась с Windows/Dota.** То, что FIX3 у тебя работал, не заменяет проверку quickcast, новых биндов и новых профилей. Синтетические проверки подтверждают логику, не игровые значения таблиц.

`killsteal.log` теперь содержит `TOGGLE ON/OFF`, `SENT`, `FEEDBACK` и диагностические `DATA`. `overlay.log` — диагностика оверлея. Если проблема повторится, нужны строка панели KS4 и эти журналы.

Офлайн: `py -3.11 -m unittest discover -s tests -v`; пример без игры: `py -3.11 demo.py`.
