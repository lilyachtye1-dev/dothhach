# HACHBOB — камера в основном меню · FIX1

**Скрипты → Камера**, сразу после Last Hit. Один ползунок и одна кнопка дымки, без отдельных окон.

## Установка

1. Выключи функции в старых ZOOM / SCENE и закрой их окна. Закрой HACHBOB через **End**.
2. Распакуй архив **с заменой в существующую папку HACHBOB**, рядом с `start.bat`.
3. Запусти обычный **`start.bat`**. Меню пересоберётся; в консоли появится строка `[Camera native FIX1]`.
4. Открой **Insert → Скрипты → Камера**. `ZOOM.bat` / `SCENE.bat` больше запускать не нужно.

Это обновление для существующей установки HACHBOB, не полный комплект. Профили, бинды, schema, globals и настройки Last Hit/KS не заменяются.

## Управление

- Новый фиолетовый ползунок с подсвеченной дорожкой, крупным значением и состоянием применения.
- Крайнее левое положение **«Авто»** отключает наш зум и возвращает исходную дистанцию / FarZ. Остальной диапазон — **1000–2200**, шаг 25.
- При перетаскивании выбирается значение. **После отпускания** оно отправляется в рабочий модуль. Клавиатурные изменения применяются после короткой паузы.
- **ZFar включается вместе с зумом**, отдельного переключателя нет.
- **«Отключить дымку» / «Вернуть дымку»** работает и при «Авто».
- Крупное число показывает выбранное значение, подпись рядом — подтверждённое модулем. Ошибка выводится в нижней части карточки и общей консоли, а также сохраняется в `overlay.log` и `zoom/integrated.log`.
- Каждый новый запуск — **Авто, обычная дымка**. Активные значения между запусками не сохраняются.
- **Insert** прячет меню, сохраняя настройки. **End** запускает возврат и завершает работу. При потере свежих команд настройки отключаются условным восстановлением.
- Туман войны и видимость скрытых противников не меняются. В `--preview` записи камеры выключены.

## Что исправлено

1. Черновик ползунка, отправленная команда и подтверждение разделены. Heartbeat больше не отправляет промежуточные значения во время drag и не меняет содержимое уже отправленного номера команды после ошибки.
2. Короткое пересечение чтения файла с атомарной заменой в Windows могло отменить включение. Воспроизведено на старом исходнике с имитацией sharing violation: старый модуль отменяет свежую команду, FIX1 — нет. Для такого случая допускается ранее проверенная команда максимум на 250 мс и только до её исходного срока действия. Ошибочный JSON, другой session, удалённый или просроченный файл этим не маскируются.
3. При повторном открытии меню с тем же feed новая команда OFF получает номер выше последнего подтверждённого, а не застревает на устаревшем счётчике.
4. Видны стадии подключения и конкретная причина отказа. Ошибки больше не остаются только в отдельном журнале камеры.
5. Если пользовательский WPF-шаблон не загрузится, остаётся стандартный контрол, а не падает страница.

**Точную причину отказа в присланной пользовательской сессии установить нельзя:** в присланных файлах отсутствует `zoom/integrated.log`, а запись controls сделана при выходе по End. FIX1 исправляет воспроизведённые дефекты обмена, но не выдаётся за подтверждённый live-ремонт именно той сессии.

## После обновления Dota

Не каждый патч ломает программу. Всё зависит от того, какие структуры, адреса и код изменились.

- Для обычного обновления адресов через **Настройки** нужен согласованный комплект **`client_dll.json` + `offsets.json` из одной версии игры**, а не случайный один offset. Это обновляет поддерживаемые поля schema и глобальные адреса. Изменение логики игры, формул или структуры данных иногда требует изменения кода/профилей.
- **Для камеры этого недостаточно.** Проверенные Zoom / ZFar используют отдельный профиль версии `client.dll`, адреса/сигнатуры и хеши кода; дымка использует проверенные поля и адрес системы сущностей.
- Если патч меняет проверяемую DLL, камера может отказаться включаться до обновления её профиля. Текущий импорт JSON через меню не переписывает `zoom/verified.py`, `zoom/farz.py` или `zoom/scene.py`.
- Нельзя просто убрать проверку версии или заменить хеш случайным новым значением: сначала нужно подтвердить, что адреса и смысл полей остались правильными. До этого функция должна оставаться выключенной.

## Проверка и ограничения

- **1181 тест — успешно**, без пропусков в использованной среде; в FIX1 добавлено 18 тестов, включая 19 исполняемых проверок реальной C#-модели ползунка.
- Полная компиляция C# 5 / x64 по reference assemblies .NET Framework 4.8, компилятор Mono, предупреждения считаются ошибками.
- Inline-шаблоны проверены как XML; реальное WPF-отображение на Windows здесь не запускалось.
- 28 файлов принятого exp6 сохранены побайтно. Контроллеры памяти Zoom / FarZ / дымки не переписаны. Защищённые исходники Last Hit, KS, мыши и `start.bat` совпадают с принятыми версиями.

Проверки памяти выполнялись на синтетической модели, не в живой Dota. Возврат условный: чужие изменения, другой объект или другую сцену не затираем. Принудительное убийство процесса, выключение ПК и гонки с игрой не позволяют гарантировать восстановление. После ошибки новая попытка требует явного действия пользователя, а не автоматической повторной записи.
